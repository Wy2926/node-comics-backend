# 任务执行架构

中心管理任务、调度、文本模型与结算；独立计算节点处理图像和文件。两端通过版本化 HTTPS / WebSocket 协议协作。

## 组件与状态归属

| 组件 | 职责与权威状态 | 实现入口 |
| --- | --- | --- |
| API | 用户隔离、任务受理、节点认证、分配与结果接收 | `backend/app/main.py`、`compute_channel.py`、`compute_v3.py`、`documents/compute.py` |
| control-worker / document-worker | 单页 / 整本文本调用、持久调用意图与响应、未知结果核实 | `backend/app/workers.py`、`documents/worker.py` |
| maintenance | 过期租约恢复、持久交付恢复与保留期清理 | `backend/app/dispatcher.py` |
| PostgreSQL | 任务阶段、节点配置、租约、领取回执、检查点元数据、调用记录与账本 | `models.py`、`queue_models.py`、`documents/models.py` |
| Redis | 有效期内的限流与准入状态；持久任务和回执在 SQL | `backend/app/redis_state.py` |
| 计算节点 | 接管、资源预算、执行、交付；SQLite 保存未决容量请求、租约与冻结结果 | 节点仓库 `classic_node/agent.py`、`journal.py`、`pipeline.py` |
| 文件工作目录 | 固定宿主上的源文件、规范化页、检查点与最终 ZIP | 节点仓库 `classic_node/document_runner.py`、`document_workspace.py` |

单图输入和结果在中心共享图片卷；文件源与最终 ZIP 在私有 R2。节点持有精确临时授权，模型供应商与 R2 密钥留在中心。

任务提交后由数据库通知唤醒消费者；通知仅触发重读。API 连接内的待发消息、ACK 等待和推送快照均可重建，任务进度不依赖进程内队列或通知历史。

## 接单与分配

1. 管理后台预设节点身份、执行位和能力权重；节点注册实际语言、字体、输出格式及文件能力。
2. 节点建立控制通道，用一个领取入口持久化并上报单图 / 文件空位。无任务时保持该请求，心跳和通道接收独立运行。
3. 通道所属 API 进程调用共享调度器，在数据库锁内复核能力、配置和容量，原子保存租约与领取回执后推送。
4. 节点逐项落盘接管后 ACK；按剩余资源发送下一份请求。一次分配单图批次或一个文件阶段。

### 加权规则

管理后台的 `performance_weight` 为整数 1–1000，默认 1；节点注册不能修改。候选节点须就绪、心跳新鲜、配置同步、能力匹配且有空位；通道节点还受本地上报和有效期约束。

在最多 32 个最老候选中，单图按任务冻结的服务优先级排序，逐项选择：

```text
分数 = (未释放租约数 + 本轮拟分配数 + 1) / performance_weight
```

分数越小越优先；同分依次优先在途数少、当前分配通道所属节点、节点 ID。每个通道只提交自己选中的租约，其他节点的拟分配用于本轮比较。权重 2:1、容量充足时，同类任务约按 4:2 分配；实际吞吐仍取决于执行位和处理耗时。

`execution_slots` 是服务端硬上限，逾期但尚未释放的租约仍占位；本地还受 `max_leases`、内存和计算并发限制。单图优先，文件解析 / 打包受 `document_slots` 约束；没有单图在途且无可领取单图时，文件 OCR / 渲染可借用剩余执行位。

文件仅首次 `doc_prepare` 加权选择宿主。后续阶段保持工作目录亲和性，调整权重不迁移已有文件。

## 执行流程

### 单图

```text
受理并持久化 → 分配整页租约 → 下载校验 → OCR / 分析检查点
                                              ├─ 中心整页文本翻译 ─┐
                                              └─ 节点抹字 ────────┤
                                                       嵌字 → 冻结结果 → 交付 → 终态结算
```

无字页在分析检查点直接终态。等文本不占本地计算线程，但整页租约持续占执行位。译文通过通道更新，心跳也可补齐；交付未知时重传冻结字节，收到终态才清除本地结果。

### PDF / ZIP / CBZ

```text
浏览器直传 R2 → doc_prepare（选宿主、下载、解析）→ 冻结页清单与预占额度
  → doc_ocr（逐页）→ doc_text（中心汇总整本）→ doc_render（原宿主逐页）
  → doc_zip（原宿主打包、上传 R2）→ 完成与结算
```

无字页跳过渲染，全书无字跳过文本调用。各节点阶段都从同一个控制通道接单；中间图像留在工作目录，中心只保存检查点描述与文本。文件规则与计费见[任务与额度](TASKS.md)。

## 恢复与设计边界

| 机制 | 负责的故障边界 |
| --- | --- |
| 原编号、原内容重放 + 持久回执 | 分配结果或 ACK 丢失时找回同一组租约，避免重复分配 |
| 接管后 ACK | 确认节点已落盘本批租约；只推进通道分配，不续租 |
| 独立 HTTP 心跳 | 续租并校验执行权；通道收发或大结果上传阻塞时仍能续期 |
| 空位有效期 | 通道进程每 5 秒核对，空位有效 15 秒；进程失联后清除虚假可用容量，不撤销已有租约 |
| 连接寿命 | 单连接 300 秒后重连，让切流前的代理连接自然排空；复用原编号重放 |
| 注册 / 文件 `sync` | 重启恢复租约、核对目录归属与代次；文件定期同步也负责取得清理授权 |
| 租约与目录代次 | 拒绝旧执行者和旧目录交付；本地截止后停止执行 |

节点重连重放未决容量请求，重新读取配置与租约快照。已有 HTTP 领取请求由同一个入口恢复，解析其回执后才发新编号。服务端持久回执先于配置冲突检查。

已发送但结果未知的模型调用保留意图和预占，先核实原调用；失联或失盘不能触发盲目重发。目录仅在中心明确终态、撤销或代次淘汰且本地无活动操作时清理。

领取、续租、通道接收需要独立执行；下载、计算、落盘、交付各自有界以避免相互阻塞。持久调度状态集中在 SQL，节点只保留恢复执行所需的数据；官网 / 插件 SSE 读取用户任务快照，与节点控制通道职责不同。

字段与错误边界见[计算协议](COMPUTE_PROTOCOL.md)，运行与切流见[部署](DEPLOYMENT.md)和[运维](OPERATIONS.md)。
